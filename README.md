# OTT 行业资讯聚合看板

深色资讯聚合看板，数据来自**公开页面真实抓取**，每条均保留原文链接与发布时间。

---

## 相比上一版改了什么

上一版的数据停留在 **10-13**，而今天已是 10-27，两周没有更新。根因有两个：

| 问题 | 具体表现 | 本版处理 |
|---|---|---|
| 前端内置演示数据 | 页面主体是 `DATA` 常量里写死的假数据，标题到处是「数值待补充」 | 全部移除，改为读取抓取管道产出的 `data.js` |
| 后端抓取任务停了 | `/api/articles` 只有 31 条，最后写入 10-13 | 前端重建抓取层，不再依赖该接口 |
| 日期写死 | 「今天是 10 月 10 日」是硬编码字符串 | 改为按浏览器真实时间渲染 |

## 数据管道（3 个脚本 + 1 键执行）

```
crawl.py        抓取 10 个信息源 → data/raw.json
ai_process.py   去重 / 过滤广告 / 摘要 / 分类 / 热度 → data/processed.json
export.py       生成前端数据 → data.js → 同步到看板目录
run_pipeline.sh 一键执行上面三步（失败自动重试 2 次 + 写告警文件）
```

### 信息源（全部公开，遵守 robots）

| 类型 | 信息源 | 抓取方式 |
|---|---|---|
| 行业媒体 | 流媒体网、流媒体网·OTT 频道、依马狮广电网 | 静态页解析 |
| 数据机构 | 奥维云网、流媒体网·数据 | 官方 JSON 接口 + 静态页 |
| 政策 | 广电总局·公告公示 / 政策解读、工信部·政策文件、流媒体网·政策 | 浏览器渲染（列表页 JS 加载） |
| 竞品 | 流媒体网·厂商（10 页翻页） | 静态页解析 |

> 抓不到的源会如实标记 `status: error/empty` 并写入 `error` 字段，**不会用假数据填充**。

## 溯源防幻觉（对应项目 P0 要求）

- ✅ 每条资讯都带可点击的原始链接（首屏 77 条，全部 `target=_blank`）
- ✅ 发布时间字段**只有三种取值**：真实日期 `2026-10-26` / `2026-10（月精度）` / `时间待补充`
- ✅ 月精度日期不会被伪装成具体某一天
- ✅ 摘要只压缩原标题，不引入标题之外的事实与数字
- ✅ 无链接的记录摘要自动置为「【待补充】原文链接缺失」

## AI 处理策略

| 环节 | 规则 |
|---|---|
| 去重 | URL 精确匹配 + 标题相似度 > 0.88 合并，记录 `also_in` 多源 |
| 广告过滤 | 正则命中「优惠券/招商加盟/立即购买」等 |
| 陈旧过滤 | 政策/行业 180 天；竞品动向 400 天（财报战略一年内仍可对标） |
| 分类 | 加权词典打分：政策 → 竞品 → 数据 → 行业；命中品牌名强制升级为竞品 |
| 热度 | 品类基值 + 品牌权重 + 阅量(√) + 关键词 + 时效加权 |

## 定时抓取

线上由 `.github/workflows/daily.yml` 调度，采用**状态驱动的自愈**而非单一 cron：
北京时间 00:17 主任务 + 01:43～07:43 凌晨看门狗 + 09:43 / 11:43 上午补档 + 14:23 兜底，共 8 次触发机会。
每次先检查 `data.js` 的 `generated_at` 是否已是「北京时间今天」，是则秒跳，否则立即补抓；
超过 30 小时仍未更新会开 Issue 告警。原因见 `DEPLOY.md`：GitHub 定时任务是尽力而为的，
排队任务可能被丢弃。

本地想手动跑一次完整管道（不经过 GitHub）：

```bash
export PATH="/root/.pyenv/shims:/root/.pyenv/bin:$PATH"
bash pipeline/daily.sh
```

## 已知限制（如实说明）

1. **流媒体网列表页不含日期**，需进详情页才有，本版按「时间待补充」处理，未猜测。
2. **竞品品牌覆盖不均**：海信 6 条、创维 7 条、酷开 6 条、小米 4 条、华为 2 条 —— 这反映的是站方实际刊发频率，非抓取缺失。芒果超媒、新媒股份等在现有公开源中暂无命中，建议后续接入其官网或财报页。
3. **摘要为规则引擎生成**，非大模型。若要更自然的摘要，可在 `ai_process.py` 的 `make_summary()` 处接入 LLM API，`trace` 字段已预留溯源约束位。
4. 本沙箱的 `data.js` 是**某一时刻的快照**，长期运行需部署 `pipeline/` 到有 cron 的机器。
